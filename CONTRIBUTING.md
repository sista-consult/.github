# Contribuer aux projets SISTA

1. Partir de la dernière version de `main`, puis créer une branche : `feature/…`, `fix/…` ou `doc/…`.
2. Lancer les tests sur sa machine avant d'envoyer.
3. Ouvrir une pull request vers `main` et remplir le modèle : ce qui change, comment vérifier.
4. Le chef de projet relit, puis fusionne par squash : la fusion met l'application en ligne.

À ne jamais faire :

- pousser directement sur `main` ;
- mettre dans un dépôt un fichier `.env`, un mot de passe, une clé ou des documents clients ;
- fusionner une pull request dont le contrôle est rouge.

Procédures complètes : dépôt `sista-docs` (réservé aux chefs de projet).
